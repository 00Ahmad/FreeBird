# FreeBird — Code audit (November 2026)

From the code audit on 2026-11-03 (broken functionality, broken code, dead code, performance, optimization). See the [roadmap](../roadmap.md) for feature work. `[ ]` = open, `[x]` = done.

Each item: where it is, what goes wrong, how to fix it. **(plausible)** = matches the code but wasn't reproduced. Everything else was confirmed by reading the code paths or reproduced with a script. Add a regression test with each fix.

**Status (2026-11-03):** all items fixed except three that are partly done and still open (marked below). Tests went from 215 to 305; typecheck, oxlint, Prettier, knip and the build are clean.

At audit time typecheck, oxlint and all 215 tests passed, so none of these show up in CI.

## P0 — Security

- [x] **Percent-encoded paths skip the token check** — `packages/harness/src/server.ts:95`. The hook tests the raw `request.url`, but the router decodes `%61` → `a` before matching, so `GET /%61pi/bots` without a token returns 200 (reproduced). Any local process can read chats, answer approvals, change secrets, or add an MCP connector (runs a command). Fix: decide on the matched route (`request.routeOptions.url`) and exact public routes, or register `/api` in a prefixed plugin with its own auth hook. Test `/%61pi/bots` → 401.

## P1 — Approvals and safety

- [x] **"Always allow" approves the whole tool** — `packages/harness/src/agent/approvals.ts:146`. It saves `{tool, match: null}`, so one "Always" on an "Add to cart" click auto-approves every later Buy/Delete click, and one on `use_login` gives every saved login to every bot. Fix: no "Always" for risks with a security or `acts` badge; otherwise scope the rule (`match` = risk summary, and site and/or bot).
- [x] **Visual Bots: Enter/Space press any focused button without asking** — `packages/harness/src/visual.ts:42`, `:186`; `packages/harness/src/browser.ts:1212`. Enter is judged by `lastClicked`, which Tab, typing and navigation never update; `screen_press Space` is always safe. Fix: judge Enter/Space by the live `document.activeElement`, treat Space on a button like a click, and clear `lastClicked` on Tab, navigation and `look`.
- [x] **Typing "search" makes any box a search box** — `packages/harness/src/visual.ts:28`; `packages/harness/src/browser.ts:144`, `:209`. The label includes the typed value, and `isSearchBox` matches `/\bsearch/` on the label, so after typing "search results attached" into a message box, Enter sends it with no card. Fix: decide only from `type=search`, `role=searchbox/combobox`, `aria-label`/`placeholder`/`name`; never from the value.
- [x] **`browser_click` on an unnamed button is safe** — `packages/harness/src/browser.ts:793`, `:840`. `?? "element N"` doesn't catch `""`, so icon-only trash/send/pay buttons need no approval. Fix: reuse visual's `clickRisk` (ask for unnamed buttons, and when `seen` has no entry).
- [x] **Risky-click word list misses many actions** — `packages/harness/src/browser.ts:292`, `packages/harness/src/visual.ts:24`. Misses "Move to trash", "Discard draft", "Deactivate account", "Save changes", "Reply", "Share", "Place bid", "Accept all", and every non-English label. `screen_click_at` on a non-candidate `<div>` is also safe. Fix: widen the list (trash, discard, deactivate, close account, archive, save, reply, comment, share, invite, accept, agree, bid, sell, upload), keep one shared constant, and ask when `markAt` finds no candidate.
- [x] **Secret request saves under any name the client sends** — `packages/harness/src/vault.ts:336`, `:230`. The value is saved under `body.name` but the bot is granted `args.name`, so an open request id can overwrite any secret (e.g. a provider key). Fix: store the requested name with the pending request and ignore the body's name.
- [ ] **`computer_run` is always safe but the container can reach the LAN and host** — `packages/harness/src/computer.ts:169`. The default Docker network allows the LAN and `host.docker.internal` (e.g. Ollama on :11434), bypassing the private-host approvals of `fetch_url`/`browser_open`. **(plausible)** Fix: an egress-only network, or block `host.docker.internal`, or classify LAN/host targets as ask. **Partly done:** `host.docker.internal`/`gateway.docker.internal` point at nothing in new containers, and commands naming a LAN or host address ask. **Left:** real egress filtering (a Docker network or firewall rule); an obfuscated command can still reach the LAN.
- [ ] **Local-network guard attaches asynchronously** — `packages/harness/src/browser.ts:464`, `:526`, `:564`. `page()` returns before `Fetch.enable` finishes, so a fresh tab's first redirect to 192.168.x.x can load unguarded; only `Document` requests are intercepted, so page `fetch`/`img` to LAN devices are never checked. **(plausible)** Fix: await a per-page guard promise in `page()`; also intercept XHR/Fetch to private hosts. **Partly done:** `page()` waits for the tab's guard, and XHR/Fetch are now checked too. **Left:** images and scripts aren't intercepted, nor a popup tab's very first request.
- [x] **`search_files` follows links out of the bot folder** — `packages/tools/src/builtins.ts:136`. Symlinked or hard-linked files inside the folder are read without approval, unlike `read_file`. Fix: skip `entry.isSymbolicLink()` or check `resolvePath(...).inside` per file. _Done; hard links can't be told apart from normal files (read_file has the same limit)._
- [x] **Saved logins match any subdomain** — `packages/harness/src/vault.ts:143` (used by `browser_sign_in`). A login for `sharepoint.com` / `myshopify.com` / `www.example.com` is offered to every subdomain, including attacker-owned tenants. **(plausible)** Fix: exact host by default, subdomains only on opt-in, with a public-suffix check. _Done with a short built-in list of shared domains, not the full public-suffix list. Logins that relied on subdomain matching need "Also use on subdomains" ticked._
- [x] **Destructive-command badge is wrong both ways** — `packages/tools/src/shell.ts:87`. False positives: `Get-ChildItem | Format-Table`, `git push --force-with-lease`. Misses: `ri -r -fo`, `Set-Content`, `git checkout -- .`, `Stop-Process`, `mv`. Badge only (`run_command` always asks), but the card misinforms. Fix: tighten the patterns and add aliases.

## P1 — Shared-model slot and concurrency

- [x] **The slot is held for the whole turn, including waits for the user** — `packages/harness/src/turns.ts:419`. With the default `parallel=1`, one unanswered approval, question or secret card blocks every other local bot, routine and warm-up with no limit. Fix: acquire the slot around each `provider.chat` call (wrap the provider passed to `runTurn`, or add an acquire hook in the engine).
- [x] **Helpers always pass `inheritSlot: true`** — `packages/harness/src/delegation.ts:81`, `packages/harness/src/turns.ts:419`. A cloud coordinator (or any cloud bot using `message_bot`) holds no slot, so its local helpers skip the queue: 4+ concurrent Ollama requests can load extra models or evict the shared one. Fix: record whether the turn actually acquired a slot; pass `inheritSlot` only then, and have extra parallel helpers call `runtime.run`.
- [x] **Cloud turns wait for Ollama to start** — `packages/harness/src/turns.ts:362`. `beforeModel()` runs for every provider, so right after launch a cloud bot waits up to 45 s. Fix: resolve the provider first; await `beforeModel` only when `provider.local`.
- [x] **Routing takes a local slot even for a cloud shared model** — `packages/harness/src/team.ts:60`. It can wait 30 s behind local turns, then fall back. Fix: call `runtime.run` only when `provider.local`.

## Engine and providers

- [x] **Parallel screenshots break cloud requests** — `packages/engine/src/turn.ts:323`. A `user` "(Picture from X)" message is pushed between `tool` messages of one batch (`assistant, tool, user, tool`); OpenAI and Anthropic reject that order (documented rules, not tested live). Fix: collect picture messages and push them after the batch's last `tool` message (for Anthropic, images can go inside `tool_result.content`).
- [x] **User images go to models that can't see** — `packages/engine/src/history.ts:70`, `packages/engine/src/turn.ts:113`. Nothing checks `vision` for user pictures, and the 400-message history re-sends them every turn. Fix: when `!vision`, strip `images` from user messages and add "(picture omitted: this model can't see images)".
- [x] **History summaries skip messages when text repeats** — `packages/engine/src/compact.ts:19`. The fingerprint (role, length, first 200 chars) collides on repeated routine notes or "ok", so `coveredUpTo` jumps ahead; in a repro 12 messages fell out of both summary and window. Fix: store message ids (or a full-content hash) in `CompactCache`.
- [x] **Written tool calls containing ``are lost** — `packages/engine/src/react.ts:99`. The fence regex ends at the first``, even inside a JSON string, so text-tool models can never `write_file` Markdown with a code block. Fix: after the "```tool" marker, extract the JSON with `firstObject()`.
- [x] **Schema flattener leaves dangling `$ref`s** — `packages/providers/src/schema.ts:21`. `$ref` is resolved before `anyOf`/`oneOf` collapse, `allOf` isn't handled, and `$defs` are stripped, so `{anyOf:[{$ref},{type:"null"}]}` breaks MCP tools on Ollama. Fix: re-resolve after collapsing (loop with the depth guard) and merge single-element `allOf`.
- [x] **Earlier turns' tool use is replayed as native tool messages to text-tool models** — `packages/engine/src/history.ts:41`. Templates without tool support drop `tool` messages, so the bot forgets earlier results. **(plausible)** Fix: when `textTools`, rewrite them into the "```tool" + "Result of X:" text form.
- [x] **OpenAI streams merge parallel calls that reuse index 0** — `packages/providers/src/openai.ts:206`. Names concatenate ("searchsearch"), causing `bad_output`. **(plausible: server-dependent, e.g. Gemini)** Fix: a new id at an existing index starts a new slot.
- [x] **A failed attempt's thinking carries into the retry** — `packages/engine/src/turn.ts:152`, `:168`. `thinking[]` isn't reset, so the retry's assistant message carries a stale thinking block and the user sees reasoning twice. Fix: reset per attempt; don't retry once reasoning has streamed (or tell the sink to discard it).
- [x] **Ending a stream early doesn't cancel the response** — `packages/providers/src/types.ts:166`. After a parse error or `[DONE]`, the body stays open and Ollama may keep generating while the engine retries. **(plausible)** Fix: in `finally`, `await reader.cancel().catch(() => {})` if not done.
- [x] **A message on the final step gets the out-of-steps reply** — `packages/engine/src/turn.ts:280`. Steered messages on step N fall through to `OUT_OF_STEPS_NUDGE` and a false "Stopped after N steps". Fix: on the last step with steered messages, return and let the harness re-run the turn.
- [x] **`shrinkOldResults` removes the user's own pictures** — `packages/engine/src/budget.ts:42`. Contradicts the "never the user's own pictures" rule. Fix: only remove pictures matching `isToolPicture`.
- [x] **Ollama model-details cache never refreshes** — `packages/providers/src/ollama.ts:118`. After re-pulling a tag, capabilities and context size stay stale until restart. **(plausible)** Fix: key by name + digest, or clear the entry after `pull()`.
- [x] **Image size limit rejects exactly 5 MB** — `packages/shared/src/messages.ts:123`. Use `4 * Math.ceil(MAX_IMAGE_BYTES / 3)`.

## Turns, group chats and delegation

- [x] **Stop / Clear chat in a group only stops the current bot** — `packages/harness/src/turns.ts:144`. The awaited responder loop goes on to the next bot (reproduced: `Ada:stopped, Bob:done`); after Clear, the next bot answers a deleted message. Fix: a per-thread stop generation that `stop()`, clear and delete bump; break the loop when it changes.
- [x] **Pair threads are "any group with 2 members"** — `packages/harness/src/delegation.ts:25`, `:315`. `message_bot` can post into the user's own 2-bot group, and dismissing a helper deletes such groups (or a 2-bot race). Fix: a `pair` thread kind or flag, filtered on in both places.
- [x] **Deleting a bot leaves orphaned or shrunken groups** — `packages/harness/src/routes/bots.ts:44`, `packages/store/src/bots.ts:157`. The member is dropped by cascade with no `thread.updated`; pair threads keep one member; a 3-member group becomes a "pair". Fix: delete pair threads, publish `thread.updated`, delete or flag groups under 2 members.
- [x] **A deleted bot's messages show as "[Moderator]"** — `packages/store/src/migrations.ts:46` (`ON DELETE SET NULL`), `packages/engine/src/history.ts:65`. Fix: mark moderator messages explicitly (part type or flag); label null-bot messages "A former member".
- [x] **Coordinators in group chats can never create helpers** — `packages/harness/src/agent/approvals.ts:77`, `packages/harness/src/delegation.ts:171`, `:335`. `spawn_bot` (and `askBeforeUse` connector tools, `use_login`) are auto-denied and the model is told "The user denied this". Fix: return "not available in group chats", and drop `spawn_bot` from tools and prompt there (or make it safe within `MAX_HELPERS`).
- [x] **Messages sent mid-turn lose their images** — `packages/harness/src/turns.ts:168`. Steering pushes `messageText` only. Fix: include the image parts.
- [x] **Follow-up turn for a leftover steered message loses its options** — `packages/harness/src/turns.ts:234`. Restarted without `delegated`/`surface`/`parentSignal`/`inheritSlot`, so a helper's approvals go to the wrong message and the coordinator's Stop no longer reaches it. Fix: keep `TurnOptions` on the active turn and reuse them.
- [x] **Two quick messages after Stop produce two replies** — `packages/harness/src/turns.ts:161`, `:203`. Both queue on `existing.done`. Fix: in `again()`, steer into a live new turn for the key instead of chaining.
- [x] **Question and secret cards stay open after Stop** — `packages/harness/src/turns.ts:435`, `packages/harness/src/agent/approvals.ts:174`, `packages/harness/src/vault.ts:225`. Fix: mark unanswered question/secret parts expired in the catch block.
- [x] **Mention and routing name matching** — `packages/harness/src/team.ts:29`, `:69`. `"@adam and @ada"` matches only Adam (reproduced); routing reply "Adam" also picks "Ada". Fix: whole-word regex over all occurrences.
- [x] **Routing fallback ignores the primary bot** — `packages/harness/src/team.ts:51`. Fix: `members.find((b) => b.isPrimary) ?? members[0]`.
- [x] **Routing uses the "Summarize this conversation" system prompt** — `packages/harness/src/team.ts:63`, `packages/engine/src/compact.ts:82`. The model may summarize instead of choosing. **(plausible)** Fix: add a one-shot `ask(provider, model, system, user, opts)` to the engine and use it here.

## Routines, catalog and webhooks

- [x] **"Run now" or editing a one-time routine cancels its scheduled run** — `packages/shared/src/routines.ts:62`, `packages/store/src/routines.ts:82`, `:109`. `nextRun` returns null whenever `lastRunAt` is set. Fix: return `at` when `at > from` and `lastRunAt < at`.
- [x] **`tick()` failures are unhandled; catch-up timer never cleared** — `packages/harness/src/routines.ts:21`, `:31`. One bad routine row can crash-loop the harness; shutdown within 2 s runs `tick` on a closed DB. **(plausible)** Fix: try/catch the tick, skip bad rows, store and clear the timeout in `stop()`.
- [x] **Webhook returns 202 when the run is skipped** — `packages/harness/src/routines.ts:138`. Fix: return 409 when running or the bot/thread is gone, as `/run` does.
- [x] **Model catalog can stay stale after adding a provider** — `packages/harness/src/catalog.ts:19`, `:50`. An in-flight load overwrites `invalidate()`; forced refresh reuses the in-flight promise. **(plausible)** Fix: a generation counter; on `force` start a new load.

## Browser, computer and tools

- [x] **`edit_file` expands `$&`, `$$`, `` $` ``, `$'` in the replacement** — `packages/tools/src/builtins.ts:120`. Corrupts PowerShell, shell and JS code. Fix: `text.replace(find, () => replace)`.
- [x] **Timeout and Stop don't end commands that leave a child running** — `packages/tools/src/shell.ts:43`. `kill()` returns early when the parent has exited but pipes stay open (reproduced: 2 s timeout took 11 s; POSIX `sleep 1000 &` hangs 1000 s). Fix: always kill the process group on POSIX / `taskkill /T` on Windows; after timeout or abort destroy stdout/stderr and resolve on `exit` plus a short grace period. _Done; on Windows a grandchild whose parent already exited (`cmd /c start /b …`) can't be found and keeps running, but the tool still returns on time._
- [x] **PowerShell output with non-ASCII text is garbled** — `packages/tools/src/shell.ts:35`. Reproduced: `café ü` → `caf� �`; per-chunk decode can also split characters. Fix: prefix `[Console]::OutputEncoding=[Text.Encoding]::UTF8;` and use a `StringDecoder`.
- [x] **Brave/SearXNG `web_search` has no timeout or abort** — `packages/harness/src/browser.ts:720`. A server that never answers hangs the tool, and blocks that bot's browser queue in every chat. Fix: `AbortSignal.any([ctx.signal, AbortSignal.timeout(15_000)])`; pass `ctx.signal` through `guarded` and `exclusive`.
- [x] **`computer_run` timeout leaves the command running** — `packages/harness/src/computer.ts:21`, `:151`. Only the `docker exec` client is killed, the result says "Exit code: 1" with no timeout note, and Stop waits up to 600 s. Fix: wrap in `timeout -s KILL <n> sh -lc …` in the container, pass the abort signal, report timeouts.
- [x] **`computer_run` missing after a restart** — `packages/harness/src/computer.ts:72`, `:158`. The `running` set fills only from `get()`. Fix: `docker ps --filter label=freebird=1` at startup or lazily in `tools()`.
- [x] **LAN hosts by name can never be opened** — `packages/harness/src/browser.ts:813`, `:558`; `packages/tools/src/builtins.ts:195`; `packages/tools/src/web.ts:7`. `nas:5000`, `router.lan`, `*.home.arpa` get no approval card, then are refused at run time with no way to approve. Fix: resolve the name in risk/run and route a refusal through an approval; add `.lan`, `.home.arpa` and single-label names to `isPrivateHost`.
- [x] **Second chat's browser call queues behind a handoff** — `packages/harness/src/browser.ts:946`. The busy check runs inside `exclusive()`, so it waits (possibly hours) instead of failing fast. Fix: check the lease and a handoff flag before queueing.

## Performance

- [x] **Millisecond timestamp in the system prompt defeats prompt caching** — `packages/harness/src/prompt.ts:18`. The prefix changes every turn, so Ollama and cloud caches re-read the whole context. Fix: round to the date/hour, or put the time in a short message after the history. (Likely the biggest single speed-up.)
- [x] **Every click waits a fixed 2 s for a popup** — `packages/harness/src/browser.ts:651`, `:1178`. Fix: listen for `context.on("page")` with `opener() === page` during the click and check after `settle()`.
- [x] **Every streamed token re-renders the whole message list** — `apps/ui/src/components/chat/MessageList.tsx:72`; `apps/ui/src/components/chat/MessageItem.tsx:23`, `:85`; `apps/ui/src/components/chat/MessageActions.tsx:26`, `:76`. Items aren't memoized, each re-subscribes to `useLibrary`, image `data:` URLs (up to 4×5 MB) are rebuilt, and a dependency-less `useLayoutEffect` forces layout per token. Fix: `memo(MessageItem)` with stable props, library lookup once as a `Set`, memoized image src, optionally batch deltas per animation frame.
- [x] **Whole-store `useUi()` subscriptions** — `apps/ui/src/components/chat/ChatView.tsx:41`, `apps/ui/src/components/Sidebar.tsx:74`, `apps/ui/src/components/BotRow.tsx:19`, `apps/ui/src/components/CommandPalette.tsx:27`, the New*Dialog files. Re-render on every `thread.activity` and ~4×/s during downloads. Fix: per-field selectors or `useShallow`.
- [x] **Full message snapshots fill the replay buffer** — `packages/harness/src/turns.ts:284`, `packages/harness/src/bus.ts:14`. Each tool step publishes a durable full copy (results up to 20 KB); ~11 MB per long turn in the 1000-event ring. **(plausible)** Fix: a part-level patch event, or collapse older `message.updated` for the same id.
- [x] **Browser actions publish durable `data.changed`** — `packages/harness/src/browser.ts:423`. They push message events out of the replay ring (forcing full resyncs) and trigger a `/api/browser` refetch each time. Fix: debounce, or make browser `data.changed` ephemeral.
- [x] **Each save reads and validates the whole message twice** — `packages/store/src/threads.ts:208`. Runs every 750 ms and on every tool start/end. Fix: an update path that writes the patch and returns the merged object.
- [x] **Every turn loads and validates 400 full messages** — `packages/store/src/threads.ts:195` (callers `packages/harness/src/turns.ts:371`, `packages/harness/src/discussion.ts:257`, `:279`). Includes base64 images and the unused `content` column. Fix: select needed columns, skip Zod for rows the store wrote, or cache per thread; store images out of line.
- [x] **Settings re-read and re-validated many times per turn** — `packages/harness/src/services.ts:51`, `packages/model-runtime/src/index.ts:35`, `:83`, `:137`, `packages/harness/src/agent/index.ts:107`, `packages/harness/src/agent/approvals.ts:39`. SQLite read + JSON parse + Zod on every `acquire`, `pump` iteration, Ollama URL lookup, `agent.settings()`, `permissions()`. Fix: cache parsed values, invalidate on `set()`.
- [x] **`</think>` check rescans the whole reply per token** — `packages/harness/src/turns.ts:302`. O(n²). Fix: search only the tail.
- [x] **No index on `thread_members(bot_id)`** — `packages/store/src/bots.ts:17`. `bots.list()` (every turn) scans per bot. Fix: new migration `CREATE INDEX thread_members_by_bot ON thread_members (bot_id)`.
- [x] **Each browser action snapshots the whole page** — `packages/harness/src/browser.ts:123`, `:834`. Computes style/rect for every candidate before the 60-item slice and ships all `innerText` though ≤3,500 chars are shown; `browser_read part=N` re-snapshots and renumbers.
